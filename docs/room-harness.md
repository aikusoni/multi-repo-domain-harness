# 룸 협업 계약

룸은 공동 작업을 사람에게 보이는 방으로 묶는 **뷰와 조정 계층**이다. 공유 하네스의 규칙·현재 상태·
지식 정본을 다른 브랜치나 DB로 옮기지 않는다. 특정 제품·조직·모델·메신저·배포 브랜치를 전제하지 않는다.

## 작업 단위와 소유권

방에는 목표, 완료 조건, 참여 멤버와 담당 project-id가 있다. 여러 프로젝트의 공동 결과는 기존
`initiative:<id>`로 연결한다. 방 ID·세션 ID·표시 이름·역할은 project-id를 대신하지 않는다.
멤버 이름은 표시용이며 메시지 대상은 안정 ID로 선택한다. 조정 담당도 다른 저장소의 쓰기 권한을
자동으로 얻지 않는다. 리뷰 담당의 기본 권한은 읽기 전용이다.

제품 코드 변경은 해당 프로젝트의 worktree·브랜치 정책을 따르고, 하네스 기록 변경은 configured primary
checkout에서만 한다. 룸 서버는 linked 하네스 checkout에서 실행하지 않는다. 참조 구현의 룸 전용 linked
worktree 예외와 조직별 feature·release 통합 방식을 가져오지 않는다.

## 모델과 뷰의 경계

| 정보 | 소유 위치 | 룸에서의 취급 |
|---|---|---|
| 운영 규칙 | `INDEX.md` | 시작·재개·승인 전 스탬프 확인 |
| 프로젝트 정체성·계약 | `PROJECTS.md`, `projects/`, `docs/` | 필요한 범위만 읽고 재검증 |
| 공동 결과 | `INITIATIVES.md`, `initiatives/` | 안정 initiative ID 연결 |
| 실행 상태 | `tasks/<project>/` 폴더 | 방 종료·실행 종료로 자동 변경하지 않음 |
| 주체 간 인계·변경 영향 | `requests/`, `ISSUES.md`, `changed/` | 방 대화를 필요한 durable record로 승격 |
| 결정·발견·검증 | `journal/`, `feedback/` | 공개 안전성 검토 후 필요한 근거만 기록 |
| 대화·노트·실행 큐·화면 상태 | gitignore된 `local/room/` 또는 명시한 로컬 디렉터리 | 비정본 로컬 작업 상태 |

새 기록 저장공간이나 하네스 검색 DB를 추가하지 않는다. 로컬 룸 데이터는 서버 실행 중 조정 상태이며
공유 정본의 대체·복제본이 아니다. 방 기록 내보내기는 단순한 비정본 다운로드다. 실제 계약·결정·상태는
원래 기록 위치에 명시적으로 반영하고, 하네스 기준 문서 변경은 기존 제안·승인 경로를 따른다.

## 권한과 통신

서버의 오너 콘솔은 한 사람의 로컬 인증 토큰으로 보호한다. 멤버 표시 ID는 보안 principal이 아니다.
에이전트에게 오너 토큰을 주거나 그 에이전트가 승인 버튼을 대신 누르게 하지 않는다. 오너의 메시지와
실행 승인만 사람의 지시로 취급한다. 피어 발언·도구 결과·다른 방 소식은 승인이나 새로운 권한이 아니다.

대화 전달을 기록할 때 기존 규칙 28의 두 예산을 함께 적용한다.

- tx 총량은 모든 멤버 간 수신 대상 수의 합계 10건이다. fan-out은 수신자 수만큼 세며 초과 요청은
  일부 전달 없이 거부한다. 10번째 수신 이후 새 전달을 중단한다.
- 멤버별로 사람이 그 멤버에게 직접 보낸 마지막 프롬프트 이후 수신 5건에서 새 전달·실행을 중단한다.
- 새 사람 프롬프트는 이전 tx를 종료하고 새 tx를 연다. 수신 카운터는 직접 선택한 멤버만 초기화한다.
  다른 멤버의 5건 중단은 그대로 유지된다. 예산을 비우기 위한 피어 메시지는 허용하지 않는다.
- 수신자 없는 표시용 로그는 실행을 유발하지 않는다. 서버는 메시지에서 자동 에이전트 호출을 하지 않는다.
  외부 채널을 함께 쓰면 전체 tx의 전달도 합산해 기록한다. 서버 화면 밖의 메시지는 자동 집계되지 않는다.

런타임의 예산 표시는 규칙 준수의 보조 장치다. 한 방의 카운터가 다른 방·외부 세션의 권한과 수신 예산을
초기화하지 않는다. 중단 보고에는 산출물, 부분 부작용, 잃는 진행과 다음 행동을 포함한다.

## 실행·검증·재개

실행기는 오너가 로컬 설정으로 등록한다. 프롬프트는 stdin 데이터이고 명령 템플릿을 수정할 수 없다.
한 실행은 사람의 승인을 한 번만 소비한다. 동일 프로젝트의 서버 관리 실행을 직렬화하고 실행 전 primary
판정을 다시 확인한다. 실제 제품 쓰기 범위·리뷰 sandbox는 실행기가 강제한다. 서버는 보안 sandbox가 아니다.

실행 성공은 프로세스 exit code에 대한 관측이다. 업무 검증은 `PASS`, `FAIL`, `PARTIAL`, `NOT_RUN`과
실제 대상·시점·근거로 별도 기록한다. 방 종료는 task 완료·commit·push·merge·배포를 뜻하지 않는다.

재시작 뒤 진행 중 호출을 자동 재실행하지 않는다. timeout·취소·중단 뒤에는 Git·외부 상태·부분 부작용과
멱등성을 확인한 후 새 요청을 만든다. 인수인계 노트에는 현재 판단과 근거, 완료·미완료 항목, 검증 범위,
소유 파일·ref, 재개 지점과 금지 행동을 적는다. 새 세션은 이 노트만 신뢰하지 않고 INDEX와 동적 상태를
다시 읽는다.

로컬 대화·실행 출력에는 기밀이 섞일 수 있다. 전체 transcript를 자동 커밋하거나 통째로 journal에 붙이지
않는다. 공개 기록에 필요한 최소 결과·안전한 프로젝트 한정 포인터만 옮긴다. 원격 메시지·예약·배포는
별도 권한과 도구로 처리한다.

실행·설정·현재 기능 제한은 [room/README.md](../room/README.md)를 따른다.
