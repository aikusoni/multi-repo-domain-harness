# Initiatives

Initiative는 여러 프로젝트·역할·operator가 하나의 공동 결과를 달성하기 위한 협업 단위다.

## 다른 하네스 개념과의 경계

| 개념 | 역할 |
|---|---|
| Project Profile | 참여 주체의 정체성과 책임 — 누가 하는가 |
| Initiative | 공동 결과와 통합 완료 기준 — 왜 함께 하는가 |
| Task | 한 프로젝트가 직접 수행하는 일 — 무엇을 구현하는가 |
| Request | 다른 주체에 넘기고 확인할 일 — 누가 누구에게 요청하는가 |
| Issue | 위험과 차단 — 무엇이 진행을 막는가 |
| Agenda | 사람의 결정·합의 대기 — 무엇을 판단해야 하는가 |
| Operator | 반복 실행 자동화 — 어떻게 자동화하는가 |

## 생성 기준

다음 조건을 모두 만족할 때 initiative를 만든다.

- 둘 이상의 프로젝트·역할·operator가 참여한다.
- 각자의 작업 목록을 넘어서는 하나의 공동 결과가 있다.
- 통합 완료 기준과 주체 간 조정이 필요하다.

한 프로젝트가 독립적으로 끝낼 수 있는 일이나 단일 구현 항목은 task로 관리한다.

## 운영 절차

1. `INITIATIVES.md`에 `proposed` 행을 만들고 `initiatives/<id>.md`를 작성한다.
2. 공동 목표가 승인되고 참여 주체가 합의하면 `active`로 전환한다. 승인 권한이 불명확하면
   `AGENDA.md`에서 확인한다.
3. 프로젝트별 task, 주체 간 request, 관련 issue·agenda·operator를 상세 문서에 연결한다.
4. 상태가 바뀌면 상태 정본인 등록부와 상세 문서의 진행 요약을 같은 변경에서 갱신한다.
5. 모든 완료 기준을 검증하고 참여 주체의 결과를 확인한 뒤 `completed`로 종료한다. 추진하지 않기로
   결정하면 근거와 결정 주체를 기록하고 `cancelled`로 종료한다.
6. 종료할 때 `INITIATIVES.md` 활성 행 제거, 종료 대장 한 줄 추가, 상세 문서의 `## 종료` 작성과
   `initiatives/archive/<종료 UTC YYYY-MM>/<id>.md` 이동을 같은 변경에서 수행한다.

## 종료 기록

- `completed`: 완료 기준별 충족 여부, 측정 가능한 결과, 통합 검증, 참여 주체별 최종 기여를 기록한다.
- `cancelled`: 취소 사유, 판단 근거, 결정 주체, 이미 발생한 결과, 재개 조건과 후속을 기록한다.
- 종료 대장의 판정이 종료 상태의 정본이다. 상세 문서는 판정의 근거와 결과를 소유한다.
- 종료 기록과 보관 문서는 삭제하지 않는다. 같은 논의나 작업을 다시 열 때 먼저 확인한다.

initiative의 `blocked` 상태는 요약일 뿐 게이트의 정본은 `ISSUES.md`다. 개별 task·request의 상태도
initiative 상태에서 추론하지 않고 각 정본에서 확인한다. 상세 문서에는 initiative 상태를 중복 기록하지
않는다.
