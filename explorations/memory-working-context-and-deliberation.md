# 기억·작업 문맥·숙고의 관계

**상태:** OPEN
**시작:** 2026-08-28 09:10:02 UTC
**최종 갱신:** 2026-08-28 09:10:02 UTC
**정본 여부:** 비정본 exploration

## 질문

저장된 기억, 현재 문제에 집중하는 작업 문맥, 규칙에 따른 기본 행동과 숙고는 하네스에서 어떤 관계로
설명할 수 있는가?

## 현재 종합

- Storage Space는 이용 가능한 기록과 파생 표현을 보존한다.
- Working Context는 전체 기억이 아니라 현재 문제에 선택된 제한적이고 손실 가능한 표현으로 볼 수 있다.
- 반복 가능하고 계약이 명확한 행동은 별도의 중앙 숙고 계층 없이도 규칙과 operator로 수행할 수 있다.
- 집중은 자원을 한 문제에 배분하도록 돕지만 선택되지 않은 정보·반례·다른 문제를 가릴 수도 있다.
- 모호성·충돌·권한 확대·높은 위험처럼 기본 경로로 확정할 수 없는 경우에만 문제 재검토나 사용자 판단이
  필요할 수 있다.

이 종합은 `consciousness`라는 저장공간·runtime component 또는 새 작업 게이트를 정의하지 않는다. 기존
operator·issue·agenda·Context Composer·Memory Fault 개념의 관계를 탐색하는 설명이다.

## 서로 다른 관점

### 숙고는 집중을 돕는다

- 지금 처리할 문제를 선택하고 시간·token·도구 사용을 제한한다.
- 관련 없는 입력을 억제해 한 작업을 일관되게 진행하게 한다.
- 기존 규칙으로 처리하기 어려운 문제를 재정의하고 대안을 비교할 수 있다.

### 숙고와 집중은 방해가 될 수 있다

- 처음 선택한 문제 정의나 최근 정보에 갇힐 수 있다.
- 검색됐지만 선택되지 않은 evidence와 residual을 보지 못할 수 있다.
- 기본 규칙으로 안전하게 처리할 수 있는 일까지 중앙 판단을 거치게 하면 병목과 단일 실패점이 된다.

### 기본 행동과 감독은 분리할 수 있다

- 명확하고 허가된 반복 행동은 operator와 정책이 직접 수행할 수 있다.
- 기존 경로로 닫히지 않는 예외만 검토·숙고·사용자 판단으로 넘길 수 있다.
- Memory Fault도 자동 조회로 해결되면 기본 경로에 남고, 모호성·권한·비용 한계에 도달할 때만 승격할 수
  있다.

## 가설 [미검증]

- 하네스에 필요한 것은 영구적인 `consciousness` 공간보다 task 선택, attention policy, context budget과
  예외 승격 경계를 분리한 설명일 수 있다.
- 이러한 설명은 실제 Context Composer나 Memory Fault runtime이 도입되기 전에는 새 규칙보다 exploration으로
  유지하는 편이 중복과 과도한 추상화를 줄일 수 있다.

## 열린 질문

- 여러 operator가 같은 예외 판단을 반복 구현할 때 공통 숙고·승격 계약이 필요한가?
- Working Context에서 제외한 정보와 이유를 어느 정도까지 추적해야 비용보다 이점이 큰가?
- 문제 선택 자체의 실패를 outcome feedback과 memory failure 중 어디에서 다뤄야 하는가?
- 자동 실행과 사용자 판단 사이에 별도 Reflective Layer가 필요한 실제 병목은 무엇인가?

## 하네스에 미칠 수 있는 영향

현재 없음. 기존 규칙과 future memory/runtime 문서의 관계를 설명하는 참고 논의로만 사용한다. 동일한
판단이 여러 operator에서 중복되거나 자동 context 실행이 도입될 때 별도 proposal 필요성을 다시 검토한다.
