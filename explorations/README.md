# Explorations

하네스의 정책·설계·용어와 장기 방향을 바로 결정하거나 구현하지 않고 탐색하는 비정본 토론 노트다.
작업 세션의 실제 발견·결정은 `journal/`, 구체적인 변경안은 `proposals/`, 지금 사람의 판단을 기다리는
항목은 `AGENDA.md`, 확정 규칙은 `INDEX.md`와 `docs/`에 둔다.

## 읽기 경계

- 일반 프로젝트·operator 세션의 시작 절차에서는 이 폴더를 읽지 않는다.
- 하네스 정책·아키텍처·용어·장기 방향을 논의하거나 관련 문서가 특정 exploration을 직접 연결할 때만 읽는다.
- exploration의 존재, `OPEN` 상태나 내용은 작업 게이트·우선순위·지침이 아니다.
- exploration에 적힌 가설이나 종합문을 현행 계약·사실·사용자 승인으로 인용하지 않는다.

## 작성 방식

- 파일명은 주제를 드러내는 kebab-case Markdown으로 쓴다.
- 상태는 `OPEN`, `DORMANT`, `CONCLUDED` 중 하나로 표시한다.
- 시작·갱신 시각은 `YYYY-MM-DD HH:MM:SS UTC`로 기록한다.
- 본문은 append-only 대화록이 아니라 현재까지의 질문·관점·종합을 읽기 좋게 다시 쓸 수 있다. 과거 형태는
  Git 이력으로 보존한다.
- 확인된 사실·외부 근거와 `[미검증]` 가설을 구분한다. 토론이라는 이유로 공개 위험 정보 검토를 생략하지
  않는다.
- 특정 사람·세션의 발언 순서보다 질문, 서로 다른 관점, 열린 쟁점과 가능한 영향을 보존한다.

## 승격 경로

exploration은 다른 하네스 상태를 자동으로 만들지 않는다.

- 구체적인 기준 변경안이 생기면 `proposals/`에 별도 문서를 만든다.
- 지금 사람의 결정이 필요하면 근거를 proposal 또는 request에 연결하고 `AGENDA.md`에 등재한다.
- 한 주체가 실행할 일이 확정되면 task, 다른 주체에 넘길 일이면 request를 만든다.
- 승인된 결론만 `docs/`, `docs/decision-log.md` 또는 `INDEX.md`로 승격한다.
- 승격 뒤에도 exploration은 사고 과정의 비정본 기록으로 남길 수 있으며, 승격 대상을 문서에 연결한다.
